## The short version

The suite is fast (45 s), has no sleeps or retries, one consistent pattern, and every red now maps to a recorded BUG id. Fix first: CI is red on every run because problem_user jobs are red by design, so a new break in those flows looks identical to the usual red. That gate is also the cheapest fix because the BUG tags now exist to build it from. The suite is a usable release signal for standard_user (green, 45 s) and not for problem_user, by design. Not run: a fresh clone.

## What is good

- No sleeps, no retries, no `try` around locators. Waiting is web-first assertions only.
- Every red is now a tagged known bug, and the design's per-user table matches what runs (T12 now cites BUG-02).
- `seedCart` seeds below the UI so a catalog bug cannot break the Given of a cart or checkout test. Keep it.
- Page objects as fixtures, `data-test` via `testIdAttribute`, named assertions (`expect(locator, "label")`).
- Seeded randomness with the seed attached to every test; CI matrix per suite and user so user-specific bugs show as a difference between jobs.
- `check:tags` fails the build when a test lacks exactly one user tag.
- Known bugs stay red as tests, not skips. The decision is written in the design and is consistent.

## Coverage gaps

Against `2- Test Cases - Product Coverage.md` and `3- Bug Report.md`.

- Product display, "every product shows an image, title, price, description": image identity is not checked (BUG-10, manual). Detail page compares name only (`catalog.spec.ts:51`).
- Generate PDF: name and size only (finding 3). Blocked for problem_user by BUG-02.
- Checkout, "not allowed with an empty cart": covered for problem_user only and on a loose oracle (decision (b), `checkout.spec.ts:126-135`).
- Login, spaces in username: problem_user only (decision (b)).
- BUG-08: see finding 4.
- Not in either document and not tested: logout, menu links, badge after reload, totals, cancel (finding 8).
- Design table wording: T12 says "red at the last name step"; the assertion that fails is the postal code one (`checkout.spec.ts:105-108`), caused by the unfilled last name. Cosmetic.

## Suggested order

1. Finding 1 together with finding 2: tag BUG ids only on problem_user tests, validate ids against the bug report, then build the CI expected-failures gate from those tags. The tags are now complete, which is what makes this possible today.
2. Finding 4: split BUG-07/08 into a deterministic test, so the BUG-08 row stops being "partial".
3. Finding 8 (list exclusions in the design, 10 minutes) and finding 5 (one line). Leave 9 alone.

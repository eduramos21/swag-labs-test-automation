# Suite audit: swag-labs-test-automation

Date: 2026-11-23. Stack: web (ts-playwright, Chromium only, root `e2e/`). 27 tests (25 designed plus 2 session-setup tests), 0 skipped. Full local run: 44.4 s, 18 passed, 9 failed. All 9 failures are the documented red-on-purpose tests (7 problem_user, 2 standard_user: BUG-15 and BUG-01). CI history: 6 runs, all red (`gh run list`), the latest still running when checked.

## The short version

This is a well-built suite. It is fast, readable, has no sleeps, and traces every test to a design row. The problem is not the code, it is the signal. 9 of 27 tests are red on every run by design, so CI has never been green and no run can say "nothing new broke". A real regression in cart, checkout or login will sit among nine reds that everyone has learned to expect. Fix that first (a gate on the unexpected failure set, without skip or test.fail). As a release signal today it cannot be trusted for "is it safe to ship". It can be trusted as a bug-report generator.

## What is good

- Speed: 44 s locally, no sleeps anywhere (`grep` for `waitForTimeout`, `try`, `retries` over `tests/ pages/ fixtures/` finds nothing). Do not add retries.
- `seedCart` writes the cart straight to local storage so a catalog bug cannot break the Given step (fixtures/index.ts:58-72). The failure points at the thing under test. This is the layering instinct done right.
- Login reuse through `auth.setup.ts` with a setup project dependency (`playwright.config.ts` projects). `login.spec.ts` alone uses the real form. Keep this.
- Known bugs stay as honest failing tests that assert intended behaviour, each tagged `@BUG-xx`, with a README table of what is red and why (README.md "Red on purpose"). The problem is the CI gate, not this choice.
- Seeded random picks with the seed attached to the report (fixtures/index.ts:77-80). Replayable with `SEED=<n>`.
- Design and tests line up: 25 designed tests, 25 found. The "not covering" and "explore instead" tables say what is deliberately left out.
- Page objects exposed as fixtures, steps phrased Given/When/Then, and `data-test` ids through `testIdAttribute: 'data-test'`.

## Coverage gaps

Against `qa/design/swag-labs.md`:

- T1 to T13: all have a test. No design row is missing.
- T11: filename convention differs from the design (finding 5). The design also says T11 is "merged into T10 run"; it is, but only for standard_user, as intended.
- T13: oracle is provisional (swag-labs.md:78, checkout.spec.ts:93).
- problem_user for T4, T5, T12, T13 are deliberately not covered (swag-labs.md:49). Reasonable, but it is a bet that problem_user shares those code paths; BUG-01 and BUG-15 were found on standard_user only.

Absent from the design itself, so absent from every metric:

- Logout, and what a session does after logout.
- Direct URL access to inventory/cart/checkout without logging in (only locked_out_user is checked, `login.spec.ts:25-28`).
- Checkout overview totals: item total, tax, total. The overview test checks quantity and description only (`checkout.spec.ts:24-29`), not price arithmetic. This is the money path.
- Checkout cancel buttons, "Back Home", and cart state after finishing an order.
- Cart persistence across reload or navigation.

## Suggested order

1. Make CI tell known red from new red (finding 1). Everything else is worth less until a green build is possible. Keep the tests unchanged.
2. Pin the seed in smoke and test, and stop running smoke twice (findings 2 and 3). Together they make the expected-failure list stable and the results unambiguous. Both are one-line changes.
3. Confirm the T11 and T13 oracles and add an overview totals check to the design (findings 5 and coverage gaps). Cheap, and it covers the money path no test touches today.
